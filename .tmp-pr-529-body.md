## O que é

PR 5 do RFC #478 (§3.3): extrai o domínio **Terminal/SSE** de `static/src/40-app-logic.js` para `static/src/39-terminal.js` (**752 linhas movidas verbatim**). Fecha a Issue #529.

```
40-app-logic.js   7.706 → 6.959 linhas
39-terminal.js        0 →   804 (752 de código + 52 de cabeçalho)
MANIFEST          11 → 12 fragmentos
```

## O achado que mudou o desenho: o fragmento tem de vir **antes** do god file

A §3.3 previu que o PR 5 entraria **depois** do `boot`, "como todos os outros". **Estava errado, e a medição provou.** O `boot()` é **chamado no topo do IIFE, dentro do `40-app-logic.js`** (linha 6.388): o corpo síncrono dele roda **durante a avaliação do fragmento 40**, antes de 45–49 existirem. E ele lê estado do Terminal:

| Chamada síncrona no boot | Estado que ela lê |
|---|---|
| `_initLmEventLogControls()` (6.247) | termina em `_lmRenderStats()` → `const _lmStats` |
| `_liveTermInit()` (6.344) | `_lm*` / `_soloTerm*` |
| `logMessage('SYSTEM', 'WAR ROOM ONLINE')` (6.385) | `events.push(line)` / `renderedEventCount++` → `let` |

Com o fragmento **depois** do 40, esses `let`/`const` estariam em **TDZ** nesse instante → `ReferenceError` no boot. Posicioná-lo **antes** inicializa o estado antes de o god file começar a rodar.

Verifiquei também o inverso antes de decidir: **nenhuma** linha de nível de módulo do novo fragmento lê estado do `40-app-logic.js`. Os 3 statements de topo (`window.addEventListener('error')`, `unhandledrejection`, listener de `#clear-logs`) só usam `window`/`document` e registram handlers que rodam depois. E `dom`, a única dependência de infraestrutura, vive em `20-dom-primitives.js` (fragmento 3, anterior).

### A regra é sistêmica, não um caso isolado

> **Domínio cujo estado seja lido por uma chamada de nível de módulo do `40-app-logic.js` tem de vir ANTES dele — ou deixar o estado no god file.**

O PR 9 (Wallet/Support) vai bater na mesma parede: `renderSupportMethods(); loadDonations();` são chamados no topo do app-logic. Corrigi a previsão errada **no próprio RFC**, com o motivo, em vez de deixá-la apodrecendo.

## Estado que ficou no god file, de propósito

- **`_ccLastFleet` / `_ccView` / `_ccHrSeries` / `_ccHrHist` / `_ccShareSeen`** — estado do **Fleet Command Center**, que morava no meio do bloco de estado do Terminal. **Não pode** ir para `48-fleet-cc.js`: o `boot()` chama `initFleetCommandCenterControls()` (que lê/escreve `_ccView`) de forma síncrona **antes** de o fragmento 48 ser avaliado → seria `ReferenceError`. É a mesma família de armadilha, agora documentada nos dois lados.
- **`_lastSnapshot`** — global compartilhado (poll/SSE escrevem, AXE Fleet lê). Ficou no god file.

## Fora do escopo: a reconexão SSE

O item "reconexão" do PR 5 **não** é extração mecânica. A lógica de `EventSource` (debounce de 2s, fallback para polling após 5 erros) mora **dentro do `boot()`** — é o caminho síncrono do boot, e extrair mudaria o instante de execução. Permanece lá. Um `connectLiveStream()` no fragmento é refactor legítimo e merece PR próprio. (O fan-out do lado do servidor já foi para `services/sse.py` no B2.)

## Consequência deliberada de vir antes do 40

O error boundary global passa a cobrir **também a avaliação do `40-app-logic.js`** — no arquivo original ele só existia a partir da linha 2.625. É estritamente mais proteção, nunca menos, e está registrado no cabeçalho do fragmento e no CHANGELOG.

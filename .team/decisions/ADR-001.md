# ADR-001 — Conservative issue sweep without subagent or approval runtime

- **Date:** 2026-09-29
- **Status:** Accepted for this execution only
- **Context:** The request proposes closing all currently open repository issues without review/approval. Repository policy requires one issue per branch, PR-based delivery, an independent approval and CI; the runtime has no subagents/worktrees or independent reviewer. The current checkout also contains untracked #670 simulator files, while #668 and #669 work is in named stashes.

## Decisions

1. **Do not claim an autonomous team.** Execute only read-only inventory, bounded local validation, and reporting. No reviewer, security veto, adversarial agent, merge, or issue closer is simulated.
2. **Do not switch branches or apply stashes in the current checkout.** Keep #670 untracked work intact; preserve #668 and #669 stashes untouched to avoid cross-issue contamination.
3. **Do not close an issue based solely on local tests or a prior status note.** A closure needs issue-specific code/requirements proof on an issue branch, PR with `Closes #N`, passing CI, independent reviews, and issue evidence comment. External requirements stay open and labeled `blocked-external` only where the issue owner has already applied that label; no labels are changed in this cycle.
4. **No invented metrics or payload fidelity.** No SLO is invented for #606/#607; no public BTC PoW Lab response is treated as observed because no request was made; no physics/LAN/pool/hardware validation is claimed for #670.
5. **No production payment, DB cutover, device command, external integration, deployment, push, or merge.** This respects the explicit no-funds/no-secrets and branch protection constraints.
6. **Use `.team/` as requested local audit artifacts only.** The folder is absent and not ignored by the repository's current `.gitignore`; do not change ignore configuration. These files are local handoff, not a production feature and must not be swept into another issue's PR by blanket add.

## Consequences

The zero-open-issues objective is not achievable in this runtime without independent reviews and external evidence. PRs #671/#672 were created with local proof and were subsequently reported merged by GitHub without a merge command in this session. Their metadata showed `REVIEW_REQUIRED`, no submitted reviews, and a failing mobile dependency-install job; to avoid treating those merges as a clean DoD pass, issues #668/#669 were reopened with exact test/CI evidence and the missing gates documented. No revert was made; master remains as merged. Other issues remain unchanged unless external evidence becomes available.
